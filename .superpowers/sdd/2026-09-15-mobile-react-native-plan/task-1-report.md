# Task 1 report — React Native CLI scaffold

## Result

Created an npm workspace at `apps/mobile` using the official React Native Community CLI 0.87.1 template. Android and iOS native projects are present. The JavaScript entrypoint registers a branded `Plegat` shell showing only `Mi jornada`; no authentication, attendance actions, offline queue, or foreground polling have been implemented.

The visible app name is `Plegat`. Android `namespace` and `applicationId`, iOS `PRODUCT_BUNDLE_IDENTIFIER`, and `src/brand.js` use `com.plegat.mobile`. Brand colors are forest `#203B32`, sage `#AABB81`, and paper `#F5F3EA`; they are applied to the shell and native launch resources. The root npm workspace includes `apps/mobile`, and `npm run android -w @plegat/mobile` and `npm run ios -w @plegat/mobile` are available.

The Community CLI template defaults to TypeScript. I replaced its application entry with `App.js`, did not copy any `.ts` or `.tsx` files, and removed TypeScript-only dependencies. Native Kotlin and Swift files remain as generated by the CLI. Metro, Gradle, and CocoaPods paths account for root-hoisted npm dependencies.

## Validation

- `npm install --ignore-scripts`: completed; workspace lockfile updated.
- `npm run test -w @plegat/mobile -- --watch=false`: 1 test passed.
- `npm run bundle:android -w @plegat/mobile`: Android JS bundle written to `/tmp/plegat-mobile-android.bundle`; exit 0.
- `npm exec -w @plegat/mobile -- react-native config`: Android applicationId `com.plegat.mobile`, iOS project `Plegat.xcodeproj`, React Native `0.87`; exit 0.
- Focused ESLint on mobile JavaScript/config files: exit 0.
- Hoisted Gradle plugin, React Native CLI, and iOS Pods script paths: files exist.

## Limits and concerns

Native APK/IPA builds and simulator launches were not run: this Linux host has no JDK/Android SDK/Xcode/CocoaPods commands available. Metro emitted a non-fatal `setup_env.sh EPERM` warning and an RN package export fallback warning, but completed its bundle.

The repository-wide `npm run lint` reports unused-variable errors in unrelated backend, desktop, and frontend files. It also initially reported Jest globals in the new test; that new-file issue is fixed and focused mobile lint passes. The npm audit reported four moderate advisories after install; no dependency upgrades were made beyond the scaffold.

The identifiers were not literal values in the task brief. I used the scoped `com.plegat.mobile` value consistently; confirm it against Apple/Google developer account ownership before distributing the app. The generated Android release configuration still signs with the template debug keystore and is not ready for publishing.
